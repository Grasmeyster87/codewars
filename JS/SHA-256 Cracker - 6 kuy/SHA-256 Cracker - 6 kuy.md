<div class="markdown prose max-w-none mb-8" id="description"><p>This kata aims to show the vulnerabilities of hashing functions for short messages.</p>
<p>When provided with a SHA-256 hash, return the value that was hashed. You are also given the characters that make the expected value, but in alphabetical order.</p>
<p>The returned value is less than 10 characters long. When the hash cannot be cracked with the given characters return <code>nil</code> for Ruby and Crystal, <code>None</code> for Python,  <code>null</code> for Java and Javascript, <code>NULL</code> for C.</p>

<div class="markdown prose max-w-none mb-8" id="description"><p>Мета цієї ката — продемонструвати вразливість хеш-функцій у випадку коротких повідомлень.</p>
<p>Отримавши хеш SHA-256, поверніть вихідне значення, яке було захешовано. Вам також надається набір символів, з яких складається шукане значення, але в алфавітному порядку.</p>
<p>Довжина шуканого значення становить менше 10 символів. Якщо хеш не вдається розшифрувати за допомогою наданих символів, поверніть <code>nil</code> (для Ruby та Crystal), <code>None</code> (для Python), <code>null</code> (для Java та JavaScript) або <code>NULL</code> (для C).</p>

Як це працює:

chars розбивається на масив літер — це той самий набір, лише в іншому порядку складає відповідь.
permutations — генератор за алгоритмом Хіпа: перебирає всі n! перестановок масиву, але не зберігає їх усі в пам'яті одразу, а віддає по одній (yield). Це важливо, бо для 9 символів це 362 880 варіантів, а для 10 — вже 3 628 800.
На кожній перестановці рахуємо SHA-256 через вбудований модуль crypto і порівнюємо з заданим хешем.
Збіг — повертаємо рядок. Перебрали все і не знайшли — повертаємо null (саме так, а не undefined, щоб пройшов strictEqual).

Чому алгоритм Хіпа, а не arr.sort() + перестановки по черзі: він генерує кожну наступну перестановку однією транспозицією (обміном двох елементів) від попередньої, без рекурсії та без побудови проміжних масивів — тому це найшвидший з класичних способів обходу всіх перестановок, що й критично при 9-10 символах.


## `sha256(str)`

```js
function sha256(str) {
```
Допоміжна функція-обгортка над Node'вським модулем `crypto`.

```js
  return crypto.createHash('sha256').update(str).digest('hex');
```
- `crypto.createHash('sha256')` — створює об'єкт-хешер, налаштований на алгоритм SHA-256.
- `.update(str)` — подає рядок `str` на вхід хешера (переводить його в байти й прогоняє через алгоритм).
- `.digest('hex')` — завершує обчислення та повертає результат у вигляді hex-рядка (64 символи), а не Buffer'а — так його зручно порівнювати з рядком `hash` з умови.

## `permutations(arr)` — генератор

```js
function* permutations(arr) {
```
`function*` — це генератор: замість того, щоб одразу повернути результат, він може призупинятись на `yield` і віддавати значення по одному, продовжуючи з того ж місця при наступному виклику `.next()`. Тут це потрібно, щоб не тримати в пам'яті всі `n!` перестановок одночасно.

```js
  const n = arr.length;
  const c = new Array(n).fill(0);
```
- `n` — кількість елементів для перестановки.
- `c` — масив-лічильник алгоритму Хіпа, по одному лічильнику на кожну "позицію" рекурсії. Спочатку всі нулі.

```js
  yield arr.slice();
```
Віддаємо початковий порядок елементів (копію масиву — `.slice()`, щоб подальші мутації `arr` не зіпсували вже віддане значення).

```js
  let i = 0;
  while (i < n) {
```
`i` — поточний "рівень" алгоритму. Цикл працює, поки не перебрали всі рівні від 0 до n-1.

```js
    if (c[i] < i) {
```
Головна умова алгоритму Хіпа: якщо лічильник на рівні `i` ще не вичерпав свій ліміт (менший за `i`) — робимо ще один обмін на цьому рівні.

```js
      if (i % 2 === 0) {
        [arr[0], arr[i]] = [arr[i], arr[0]];
      } else {
        [arr[c[i]], arr[i]] = [arr[i], arr[c[i]]];
      }
```
Сам обмін елементів (деструктуризація для swap без тимчасової змінної):
- якщо `i` парне — міняємо місцями елемент на позиції `0` і на позиції `i`;
- якщо `i` непарне — міняємо місцями елемент на позиції `c[i]` і на позиції `i`.

Саме це чергування (парний/непарний рівень) і є "трюком" Хіпа, який гарантує, що кожна наступна перестановка відрізняється від попередньої рівно одним обміном.

```js
      yield arr.slice();
```
Віддаємо нову перестановку (знову копію).

```js
      c[i]++;
      i = 0;
```
- Збільшуємо лічильник поточного рівня — наступного разу на цьому ж рівні буде інший обмін (або умова `c[i] < i` стане хибною).
- Скидаємо `i` на 0 — алгоритм завжди повертається на найнижчий рівень після кожного обміну, це і є рекурсивна природа алгоритму Хіпа, розгорнута в цикл.

```js
    } else {
      c[i] = 0;
      i++;
    }
  }
}
```
Якщо лічильник на рівні `i` вичерпано (`c[i] >= i`) — обнуляємо його й переходимо на рівень вище (`i++`). Коли `i` досягне `n`, цикл `while` завершиться — всі перестановки видано.

## `sha256Cracker(hash, chars)`

```js
function sha256Cracker(hash, chars) {
```
Головна функція кати: приймає шуканий хеш та символи (у алфавітному порядку).

```js
  const letters = chars.split('');
```
Перетворюємо рядок символів у масив окремих літер, бо `permutations` працює з масивом, а не рядком.

```js
  for (const perm of permutations(letters)) {
```
`for...of` вміє ітеруватися по генераторах напряму: на кожній ітерації викликається `.next()` генератора, і цикл отримує чергову перестановку — доки генератор не завершить роботу.

```js
    const candidate = perm.join('');
```
Збираємо масив літер назад у рядок-кандидат.

```js
    if (sha256(candidate) === hash) {
      return candidate;
    }
```
Рахуємо SHA-256 кандидата і порівнюємо з цільовим хешем. При збігу — одразу повертаємо кандидата, не чекаючи решти перестановок (саме тут і проявляється перевага генератора над "спочатку згенеруй усі перестановки, потім перебери" — зайва робота просто не виконується).

```js
  return null;
}
```
Якщо цикл дійшов до кінця (всі `n!` варіантів перевірено, збігу немає) — повертаємо `null`, як вимагає умова кати для JavaScript.
